Fraction Equivalence Tutor

A web app that teaches 9-year-olds fraction equivalence through interactive bars and circles, guided by Lila — a scripted voice tutor. Students split, shade, smash, and compare shapes; when two colored regions line up, the equivalence is visible.

How it works

The app presents fraction bars (and later, pie-style circles). Gestures drive everything — there is no toolbar. A scripted tutor watches the student's actions and responds at key moments: when the colored portions of two bars match, when an answer reveals a specific misconception, when the playground screen is cleared. Every line of dialogue lives in equivalence.json; there is no LLM in the runtime path.

GestureEffect
Tap a pieceColor it / un-color it
Double-tap a pieceSplit it into two halves
Long-press a pieceSmash the whole bar / circle (playground only)
Drag onto neighborCombine adjacent same-colored pieces
Double-tap empty spaceAdd a new bar (or circle, when asked)

Lesson structure

The lesson is an 8-step progression authored as a graph of JSON nodes:

  1. Hook — 1/2 and 2/4 side by side: what do you notice?
  2. Color and cut — color a 1/1 bar, watch it cut into 2 equal pieces.
  3. First equivalence — cut a second bar into 4 and color 2; see 1/2 = 2/4.
  4. Second equivalence — build any equivalent of 2/3 (4/6, 6/9, …).
  5. Non-example — 1/2 vs 1/3: the regions don't line up.
  6. Circles — restate the same lessons with pie-style circles.
  7. Playground — add bars and circles, build equivalents, smash the screen clear.
  8. Done!

Node types

  • message — tutor speaks; student taps Continue to advance. May carry a setup that configures bars/circles.
  • prompt — 2–3 tappable options; correct answer is shuffled, "I'm not sure" stays pinned.
  • wait_for_action — advances when the manipulative state matches a condition. A scripted hint appears after a configurable timeout.
  • check — assessment branch (same shape as prompt).

Conditions

  • fraction_equals — cross-multiplication match (1/2 matches 2/4, 3/6, …).
  • fraction_exact — literal numerator / denominator pair.
  • action_performed — a specific gesture (ADD_BAR, SHADE, SPLIT, …).
  • screen_clear — no bars and no circles (playground finale).

Architecture

Four layers. The engine and runner are content-agnostic; lessons are pluggable JSON.

┌──────────────────────────────────────────────────────┐ │ UI Layer │ │ FractionWorkspace · TutorPanel · ProgressIndicator │ │ FractionBar / FractionCircle / Segment · Splash │ ├──────────────────────┬──────────────┬─────────────────┤ │ Manipulative Engine │ Tutor Layer │ Voice Layer │ │ (useReducer) │ (useLessonRunner)│ (useTutorVoice)│ │ │ │ │ │ - Bars + circles │ - JSON script│ - Calls proxy │ │ - Split, shade, │ - Step graph │ /tts │ │ combine, smash, │ - Conditions │ - Mute toggle │ │ add bar/circle │ - Hint timers│ │ └──────────────────────┴──────┬───────┴────────┬────────┘ ▲ ▼ ▼ └── dispatches ───────┴── Worker proxy ┘ (POST /tts)

Manipulative engine

A useReducer owning two arrays — bars and circles. Bars are ordered segments with a shaded flag and an optional free-movement offset; circles are {slices, shaded}. After every action, normalizeBars packs each bar's shaded count to the left so the visual is always contiguous-from-left, even if a path produced non-contiguous state.

ID counters (makeBarId, makeSegmentId, makeCircleId) are monotonic and not reset between setups — earlier code reset them on SET_STATE, which collided with IDs still in React's reconciliation tree and produced mixed-color, duplicate-numbered segments across setup boundaries.

Tutor runner

The runner is a hook (useLessonRunner) that tracks the current node. Two effects watch state: one re-evaluates fraction_equals / fraction_exact / screen_clear on every change to bars/circles; the other handles action_performed via an event channel (notifyAction). Once a condition fires, an isAdvancing lock forces allowedActions to empty for 400–600 ms so celebratory taps can't shade extra pieces during the pause.

Per-node knobs added during UX tuning:

  • setupDelayMs — defers the setup dispatch by N ms so a cut animation lands during the spoken line, not after. A catch-up runs on early advance.
  • setupAfterMessage — defers the setup until voice finishes (with a timeout fallback for muted users).
  • allowedActions — explicitly restrict gestures; inferred from the condition by default.
  • hideFractionLabels — hides the "X/Y" label so the screen doesn't spoil the answer on the cut quiz.

Voice

elevenLabsVoice.ts calls the Worker's POST /tts instead of ElevenLabs directly — the proxy holds the API key as a Cloudflare secret and streams audio/mpeg back. useTutorVoice.ts watches the latest tutor message, cancels any in-flight playback, and speaks it. It uses useLayoutEffect (not useEffect) so isSpeaking flips to true before paint — eliminating the first-load flash of the Continue button.

Fraction pronunciation. Before each TTS request, toSpokenFractions rewrites every X/Y as "X over Y" (so 1/2 → "one over two"). The on-screen label stays compact.

The Continue button is hidden until both conditions hold: voice has finished AND at least 1.5 s has passed since the message arrived. The Splash screen captures the first user gesture browsers require before allowing audio playback; sessionStorage persists the started flag so a dev-server reload doesn't bounce the student back.

UI

The UI receives state, dispatches gestures, and makes no pedagogical decisions. Empty bars carry a low-alpha tinted border + faint wash so "the blue bar" is recognizable before any pieces are colored. Long-pressing a segment with SMASH allowed triggers a CSS :has([data-holding="true"]) selector on the bar wrapper, animating the whole bar in orange so it's clear the whole thing will disappear. All touch targets are at least 48 × 48 px; segments are 100 px tall. Body font is Nunito 400–900.

Data flow

Student gesture → Segment / Circle / Workspace fires the handler → LessonShell: ├── if node forbids this gesture or isAdvancing → no-op ├── dispatches the reducer action └── calls runner.notifyAction(actionType) → Reducer updates → normalizeBars packs shaded left → Two runner effects react: ├── state change → fraction_* / screen_clear → advance in 600 ms └── notifyAction → action_performed → advance in 400 ms → New tutor message lands in state → useTutorVoice fetches audio and plays it → TutorPanel re-renders; Continue gated on isSpeaking AND 1.5 s hold

Button taps in the tutor panel (Continue, option) call advance / selectOption directly and bypass the action-notify path.

Running locally

Prerequisites: Node.js 20+, npm 10+, optionally an ElevenLabs API key (without it, the lesson runs silently but still works).

git clone <repo-url>
cd clone-synthesis-tutor/fraction-tutor

npm install
npm run dev

Opens at http://localhost:5173. Create fraction-tutor/.env:

VITE_TUTOR_API_URL=https://fraction-tutor-proxy.heila-shahidi.workers.dev

To run the proxy locally:

cd proxy
npm install
echo "ELEVENLABS_API_KEY=sk-..." > .dev.vars
npx wrangler dev   # http://localhost:8787

Type-check and build

cd fraction-tutor
npx tsc --noEmit -p tsconfig.app.json
npm run build

Vitest and Playwright are planned but not yet scaffolded.

Deployment

Frontend → Cloudflare Pages.

cd fraction-tutor
npm run build
npx wrangler pages deploy dist --project-name=fraction-tutor --commit-dirty=true

Production URL: fraction-tutor-1l1.pages.dev.

Voice proxy → Cloudflare Workers.

cd proxy
npx wrangler secret put ELEVENLABS_API_KEY   # one-time
npx wrangler deploy

Proxy URL: https://fraction-tutor-proxy.heila-shahidi.workers.dev. CORS is wildcard for the demo — lock to the Pages origin before any real production use.

Git uses a single origin remote with two push URLs (GitHub + GitLab) so one git push origin main updates both.

Offline behavior

Script and UI logic are bundled and run client-side; the page works offline once cached. The voice layer requires the proxy — without a network, lines aren't spoken but the lesson still progresses normally on Continue / option taps.
